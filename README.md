## 1. ملخص التقييم والمعمارية العامة للمشروع
مشروع شبكة برق نت اللاسلكية هو قالب **MikroTik HotSpot متقدم فائق الخفة والسرعة** مصمم للعمل كـ **Single Page Application (SPA)** هجينة.
المشروع مبني بالكامل باستخدام لغة الجافاسكريبت النقية المضغوطة (Vanilla Minified JavaScript) و CSS النقي بدون أي أطر عمل ضخمة (Zero Frameworks)، مما يجعله متوافقاً مع أقل مواصفات أجهزة الراوتر بورد (مثل RB750, RB941, RB951, RB1100, CCR) وأقدم الهواتف المحمولة.

## 2. هيكلية الصفحات والروابط: هل هي صفحة واحدة أم صفحات متعددة؟

### 🔍 السؤال: هل يظهر في المتصفح رابط منفصل مثل `b.net/login` و `b.net/status.html` أم يظل الرابط دائماً `b.net/index.html`؟
* **النتيجة القطعية:** يظل الرابط في شريط عنوان المتصفح **دائماً وبشكل ثابت: `http://b.net/index.html`** (أو عنوان IP الراوتر `http://10.10.10.10/index.html`).
* **كيف يتم ذلك هندسياً؟**
  1. عند اتصال الهاتف بالشبكة، يعترض الراوتر الاتصال ويطلب مسار مثل `/login` أو `/status.html` أو `/logout.html`.
  2. في قوالب هذا المشروع، تم وضع شرط مايكروتك فائق الذكاء في السطر الأول من كل صفحة فرعية:
     ```html
     $(if var == "")
     <script>
         window.location.href="index.html";
     </script>
     $(else)
     ... محتوى رد الـ JSON ...
     $(endif)
     ```
  3. عندما يطلب المتصفح أي صفحة بشكل مباشر (حيث تكون قيمة `var` فارغة `""`)، يُجبر المتصفح فوراً على التحويل إلى `index.html`.
  4. داخل `index.html`، يتم احتواء كل الشاشات والواجهات:
     - واجهة تسجيل الدخول (`.login`)
     - واجهة تفاصيل الاتصال والرصيد (`#status`)
     - واجهة الحظر ومنع التخمين (`#block`)
     - واجهة أسعار الباقات (`#price`)
     - واجهة نقاط البيع (`#sell-point`)
  5. يتم التبديل بين هذه الواجهات في جزء من الثانية عبر مؤثرات الـ CSS وتعديل فئات الـ DOM (`.active`, `.inactive`, `.processing`, `.success`) **دون أي إعادة تحميل للصفحة (Zero Page Reload)**.

* **الحجم الإجمالي الأساسي للتحميل:** أقل من **105 كيلوبايت** فقط (قبل تحميل صور الإعلانات الخارجية إن وجدت).
* **زمن التحميل الأولي (First Contentful Paint):** يتراوح بين **80ms إلى 200ms** على اتصال الواي فاي المحلي.

## 4. بروتوكول التخاطب وتبادل البيانات مع المايكروتك (JSON API Engine)

بدلاً من الطرق التقليدية القديمة بإرسال استمارة HTML كاملة وإعادة تحميل الصفحة، يعتمد هذا المشروع على **محرك JSON RPC عبر استعلامات AJAX**:

### 1. الاستعلام السحري `var=callBack`:
* عند إرسال أي طلب من الجافاسكريبت، يُرفق المعامل `&var=callBack`.
* يقرأ الراوتر الشرط `$(if var == "")` فيجد أن `var` ممتلئة (`callBack`)، فيقوم بتجاوز التوجيه وتفعيل الشطر الثاني `$(else)`.
* يقوم محرك قوالب المايكروتك باستبدال المتغيرات وإرجاع الرد بصيغة JSON نقي:

#### مثال استجابة `login.html`:
```json
{
  "logged_in": "$(logged-in)",
  "link_only": "$(link-orig-esc)",
  "link_login_only": "$(link-login-only)",
  "link_logout": "$(link-logout)",
  "link_status": "$(link-status)",
  "nas_id": "$(identity)",
  "ip": "$(ip)",
  "mac": "$(mac-esc)",
  "action": "onLoginStart"
}
```

#### مثال استجابة `status.html`:
```json
{
  "logged_in": "$(logged-in)",
  "ip": "$(ip)",
  "sps": "$(domain)",
  "bytes_in": "$(bytes-in)",
  "bytes_out": "$(bytes-out)",
  "remain_bytes_total": "$(remain-bytes-total)",
  "session_time_left": "$(session-time-left)",
  "uptime": "$(uptime)",
  "action": "onStatusQuery"
}
```

### 2. التنفيذ الديناميكي للأحداث:
في دالة `getRequest(url)` داخل `main.min.js`:
```javascript
var e = JSON.parse(this.responseText);
window[e.action](e);
```
يقوم النظام تلقائياً بتشغيل الدالة المناسبة لحالة الرد:
* `onLoginStart(e)`: فحص الكوكيز التلقائية وبدء الجلسة.
* `onLoggedIn(e)`: نجاح الدخول والانتقال لواجهة الحالة.
* `onLoginError(e)`: فشل الدخول وعرض نافذة الخطأ العربية.
* `onStatusQuery(e)`: تحديث عدادات التحميل والرفع والوقت المتبقي.
* `onLoggedOut(e)`: تأكيد تسجيل الخروج وإعادة واجهة الدخول.

## 5. دورة حياة تسجيل الدخول الكاملة وكيفية معالجة الكرت

1. **كتابة الكرت:**
   - يكتب المستخدم رمز الكرت في الحقل `input[username-field]`.
   - يقوم سكربت `hotInImprover.min.js` تلقائياً بحذف أي مسافات زائدة (`rm-white-spaces`) وتحويل أي أرقام عربية/فارسية إلى أرقام إنجليزية (`to-arabic-numbers`).
2. **الضغط على زر الدخول:**
   - يتم تشغيل `onLoginSubmitted()`.
   - يتم التحقق من أن خانة الكرت ليست فارغة.
   - يتم حفظ الكرت في الذاكرة والكوكيز `hot_last_username` لمدة 30 يوماً عبر `saveHotLastUsername(card)`.
   - يتغير مظهر الزر إلى حالة المعالجة الدوارة (`$loginSubmit.classList.add('processing')`).
3. **توليد وإرسال طلب الدخول:**
   - يتم قراءة السرعة المحددة من الحقل المخفي `#speed`.
   - يتم بناء الرابط:
     ```
     /login?username={USER}&password={PASS}&domain={SPEED}&var=callBack
     ```
   - **استثناء الكروت الخاصة (بادئة 777):**
     إذا بدأ الكرت بـ `777`، يتم حذف `&domain=` تماماً لتمكين كروت الإدارة والباقات الخاصة من الحصول على سرعتها الأصلية المحددة في بروفايل السيرفر.
4. **استقبال رد المايكروتك:**
   - يقوم المايكروتك بمطابقة الكرت؛ إذا كان صحيحاً يعيد التوجيه داخلياً إلى `alogin.html` التي ترجع `action: "onLoggedIn"`.
   - يتم تصفير عداد الحظر `resetCounter()`.
   - يتم إخفاء واجهة الدخول بحركة انسيابية وظهور واجهة الحالة `#status`.
   - يتم إطلاق مؤقت الرصد اللحظي `startStatusQuery()`.

## 6. كيف يتم الاتصال بالإنترنت وإغلاق نافذة تسجيل الدخول المنبثقة تلقائياً؟

### ❓ السؤال: كيف يتم الاتصال بالإنترنت فوراً بعد تسجيل الدخول وتغلق النافذة التلقائية التي تفتح عند الاتصال بالواي فاي؟
* **آلية عمل مساعد الشبكة الأسيرة (CNA - Captive Network Assistant):**
  1. عند اتصال الهاتف بالواي فاي، يقوم نظام التشغيل (Android / iOS / Windows) بإرسال طلب فحص اتصال خفي (Probe Request):
     - في أندرويد: `http://connectivitycheck.gstatic.com/generate_204`
     - في آبل: `http://captive.apple.com/hotspot-detect.html`
     - في ويندوز: `http://www.msftconnecttest.com/connecttest.txt`
  2. طالما المستخدم لم يسجل دخوله بعد، يقوم المايكروتك باعتراض الطلب وتوجيهه لصفحة `index.html` فيقوم نظام الهاتف بفتح **النافذة المنبثقة التلقائية لنظام التشغيل (System Captive Portal Popup)**.
  3. عندما يضغط المستخدم على "تسجيل الدخول" ويقبل المايكروتك الكرت عبر طلب الـ AJAX:
     - يفتح المايكروتك فوراً حركة الإنترنت (IP Forwarding & NAT) لجهاز المستخدم بناءً على عنوان الـ MAC والـ IP.
     - نظام تشغيل الهاتف يعيد فحص خوادم الاختبار (`generate_204` أو `captive.apple`) في الخلفية كل ثانية أو ثانيتين.
     - عندما يتلقى نظام الهاتف الرد `HTTP 204 No Content` الحقيقي من جوجل، يعلم النظام أن الإنترنت أصبح متاحاً بالكامل.
     - **تقوم نافذة تسجيل الدخول المنبثقة لنظام الهاتف بإغلاق نفسها تلقائياً وبشكل فوري** دون حاجة لأي تدخل من المستخدم، وتظهر علامة الواي فاي كاملة.
  4. أما إذا فتح المستخدم الصفحة يدوياً داخل المتصفح (Chrome أو Safari)، فإن الصفحة تظل مفتوحة وتعرض له عدادات الرصيد والوقت وسرعة الاتصال.

## 7. آلية تسجيل الخروج وقطع الاتصال التام

1. عند الضغط على زر "تسجيل الخروج" (`.logout-submit`):
   - يتم استدعاء دالة `userLogout()`:
     ```javascript
     getRequest("/logout?erase-cookie=yes&var=callBack");
     ```
2. يتلقى المايكروتك الطلب في ملف `logout.html`:
   - يقوم المايكروتك بحذف جلسة المستخدم النشطة من قائمة `Active Hotspot Users`.
   - يقوم بمسح كوكيز المايكروتك الخاصة بالجهاز لمنع إعادة الدخول التلقائي بدون كرت.
   - يعيد حجز الجهاز في الـ Walled Garden وقطع تصفح الإنترنت.
3. على جانب الواجهة:
   - يتم إخفاء واجهة الحالة `#status`.
   - يتم إيقاف مؤقت الاستعلام الدوري للبيانات `intervalStatus = false`.
   - يتم إظهار واجهة تسجيل الدخول مجدداً لتكون جاهزة لاستقبال كرت جديد.

## 8. نظام تحديد وتبديل السرعات المباشر أثناء الاتصال (Live Speed Switch)

### أ) اختيار السرعة المسبق (قبل الدخول):
تتوفر 5 خيارات سرعة تفاعلية يتم ضبطها في الحقل المخفي `#speed`:
1. `speed_economic` (اقتصادية)
2. `speed_normal` (متوسطة - افتراضية)
3. `speed_high` (عالية)
4. `speed_very` (فائقة)
5. `speed_gaming` (ألعاب أونلاين - تمنح أولوية للبنج)
يتم حفظ الاختيار في `localStorage` وكوكيز `speed` لمدة 30 يوماً.

### ب) التبديل المباشر بعد الدخول (من داخل صفحة الحالة):
يحتوي كرت الحالة على صندوق تبديل السرعات (`#speedSwitchBox`):
* **الخوارزمية الذكية لإعادة الدخول التلقائي (Automatic Re-login Routine):**
  1. يختار المستخدم السرعة الجديدة ويضغط "تطبيق السرعة الجديدة".
  2. يقوم السكربت بالتقاط اسم الكرت الحالي من واجهة الحالة أو الذاكرة `hot_last_username`.
  3. يتم تعيين راية الدخول التلقائي `hot_auto_relogin = 1` والسرعة الجديدة `hot_speed`.
  4. يستدعي السكربت `userLogout(true)` لتسجيل خروج فوري من الراوتر لإنهاء الجلسة القديمة.
  5. يقوم مؤقت المراقبة `armDirectRelogin()` بفحص الواجهة كل 100ms.
  6. فور رصد الخروج، يُرسل السكربت طلب تسجيل دخول مباشر بنفس الكرت والسرعة الجديدة:
     ```javascript
     directLogin(username, newSpeed);
     ```
  7. تتم عملية الخروج والدخول الجديدة خلال أقل من ثانية واحدة، ويظهر للمستخدم إشعار أخضر: **"تم تبديل السرعة بنجاح ✅"**.

## 9. نظام حجب التحديثات التلقائية ومتجر جوجل بلاي (Google Updates Blocker)

* **الواجهة:** سويتش تفاعلي (`#updateToggle` و `#updateCard`) في أسفل استمارة الدخول.
* **البيانات المرسلة:** عند تفعيل السويتش، يرسل النموذج المعامل:
  `update=choose-auto-update-off`
  ويتم تخزينه في كوكيز `update` لمدة 30 يوماً.
* **النافذة التوعوية (`#updateNotice`):**
  تنبثق نافذة جميلة تخبر العميل:
  > *"تم إيقاف التحديثات التلقائية للهاتف، وتعطيل متجر جوجل بلاي أثناء استخدام الشبكة."*
* **الربط مع المايكروتك:** يقرأ الراوتر هذا المتغير ليتم إدراج عنوان IP العميل في Address List مخصصة في جدار الحماية (Firewall Filter Rules) لحظر نطاقات وسيرفرات تحديثات متجر جوجل، مما يوفر رصيد كرت المستخدم من الاستنزاف التلقائي.

## 10. نظام الكوكيز واسترجاع الكروت السابقة بنقرة واحدة (HotCookie System)

* **ملف `js/hotCookie.min.js`:**
  * **تخزين الكروت:** يتم حفظ آخر 4 كروت تم تسجيل الدخول بها بنجاح في كوكيز `storedValues` بصيغة JSON ولمدة 30 يوماً.
  * **نافذة الكروت السابقة (`#cardsModal`):**
    عند النقر على أيقونة الكروت بجانب خانة الإدخال، تفتح نافذة منبثقة أنيقة تعرض قائمة الكروت السابقة. بالنقر على أي كرت، يتم نسخه فوراً إلى خانة الإدخال ليتمكن العميل من الدخول دون إعادة كتابة الكرت يدوياً.
  * **كوكيز آخر كرت فعال (`hot_last_username`):** يتم تحديثه دائماً لضمان استمرارية الجلسة وعمليات تبديل السرعات السريعة.
  * **مسح الكوكيز (`clearCookies`):** عند تسجيل الخروج، يتم مسح كوكيز اسم المستخدم وكلمة المرور لحماية الخصوصية.

## 11. نظام الحظر الذكي ومكافحة هجمات التخمين (HotBlocker Engine)

* **ملف `js/hotBlocker.min.js`:**
* **الإعدادات المضبوطة:**
  * عدد المحاولات الخاطئة المسموحة: `try-count=10` (10 محاولات).
  * مدة الحظر: `block-time=1` (دقيقة واحدة).
* **آلية الحماية والعد التنازلي:**
  1. عند كل محاولة تسجيل دخول خاطئة، يُستدعى `incrementCounter()` لزيادة عداد الفشل.
  2. عند بلوغ 10 محاولات خاطئة:
     - يتم حفظ طابع زمني للحظر في كوكيز `BLOCKED_TIME`.
     - يتم إخفاء استمارة الدخول وعرض واجهة الحظر الكاملة (`#block`) التي تحتوي على رسم توضيحي ونص: *"لقد تم حظرك بسبب محاولات تسجيل الدخول الكثيرة الخاطئة"*.
     - يبدأ عداد تنازلي دقيق بالدقائق والثواني عبر `initCountDown()`.
     - يمنع المتصفح كتابة أي كرت حتى انتهاء الوقت، وحينها تُزال كوكيز الحظر وتعود شاشة الدخول للعمل تلقائياً.

## 12. نظام تصحيح وتنقية المدخلات والأرقام العربية (HotInImprover Engine)

* **ملف `js/hotInImprover.min.js`:**
* مصمم خصيصاً لمعالجة أخطاء العملاء الشائعة أثناء كتابة الكروت:
  * `to-arabic-numbers`: يقوم برصد كتابة الأرقام بالأشكال العربية والفارسية (٠، ١، ٢، ٣، ٤، ٥، ٦، ٧، ٨، ٩) أو النقطتين (:) واستبدالها فوراً بالأرقام الإنجليزية (0-9) أثناء الكتابة لحظة بلحظة.
  * `rm-white-spaces`: حذف المسافات الخفية التي تضاف عادة عند نسخ الكرت ولصقه من تطبيق واتساب.
  * `to-lower` / `to-upper`: توحيد حالة الأحرف لتلائم إعدادات اليوزر مانجر في المايكروتك.
  * `only-numbers`: منع إدخال الحروف إذا كانت كروت الشبكة رقمية فقط.

## 13. محرك ترجمة وتخصيص رسائل وأخطاء السيرفر (Error Localization)

* دالة `toArabicError(e)` داخل `main.min.js` تفحص الأخطاء الإنجليزية الواردة من المايكروتك وتحولها لرسائل واضحة ومفهومة للمستخدم:

| كود / نص الخطأ الإنجليزي من المايكروتك | الرسالة المترجمة المعروضة للمستخدم |
| :--- | :--- |
| `user not found` / `invalid username` | لقد ادخلت الكرت بطريقة غير صحيحة، الرجاء المحاولة مرة اخرى |
| `simultaneous session limit reached` | المعذرة ، هذا الكرت مستخدم حالياً في جهاز آخر |
| `invalid password` | تاكد من كتابة كلمة المرور بشكل صحيح |
| `uptime limit reached` / `No more online time` | عذراً لقد انتهى الوقت المتاح لك |
| `traffic limit` / `transfer limit reached` | لقد انتهى رصيد هذا الكرت |
| `no valid profile found` | لقد انتهت صلاحية هذا الكرت |
| `invalid Calling-Station-Id` | هذا الكرت مقترن بجهاز آخر! |
| `server is not responding` | يرجى الانتظار، يتم الآن اعادة تشغيل الشبكة... |
| `web browser did not send` | يرجى محاولة ادخال الكرت مرة اخرى |

## 14. نظام الرصد والمراقبة اللحظية للبيانات والوقت (Live Status Polling)

* بمجرد إتمام تسجيل الدخول، تعمل دالة `startStatusQuery()` لإرسال طلب كل ثانية واحدة إلى `/status?var=callBack`.
* **دقة قراءة البيانات:**
  * **التحميل (Download):** يقرأ قيمة `bytes_out` (البيانات الصادرة من الراوتر نحو هاتف المستخدم) ويعرضها في خانة "التحميل" بعد تحويلها لوحدات عربية دقيقة (بايت، كيلوبايت، ميجابايت، جيجابايت) عبر `toArabicBytes()`.
  * **الرفع (Upload):** يقرأ قيمة `bytes_in` (البيانات المرفوعة من هاتف المستخدم نحو الراوتر) ويعرضها في خانة "الرفع".
  * **الرصيد المتبقي:** يقرأ `remain_bytes_total` ويعرض الرصيد الفعلي المتبقي للكرت بدون أي بونص أو تلاعب.
  * **مدة الاتصال والوقت المتبقي:** يقرأ قيم `uptime` و `session_time_left` ويحولها إلى صيغة مفهومة (مثال: `4 ساعة 15 دقيقة`) عبر `toArabicTime()`.

## 15. التوافقية العالية مع الأجهزة القديمة والحديثة (من أندرويد 4 إلى أحدث الأنظمة)

* **دعم Android 4.0 - 4.4 (Ice Cream Sandwich / KitKat) وحتى Android 14+ و iOS 17+:**
  * تم بناء الأكواد بالكامل بصيغة **ECMAScript 5 (ES5)** الكلاسيكية.
  * لا يتم استخدام تقنيات حديثة غير مدعومة في متصفحات الويب القديمة (مثل `fetch()`, `async/await`, Arrow Functions في الملفات الحساسة).

  * خط `Almarai.woff2` متوافق مع كافة محركات التصميم (WebKit, Blink, Gecko).
  * تم اختبار كافة أحداث اللمس والضغط (`click`, `submit`, `touch`) وتعمل بسلاسة فائقة.

## 16. ملاحظات التدقيق البرمجي المكتشفة وتوصيات التحسين

خلال الفحص البرمجي الدقيق لملف `js/main.min.js`، تم رصد الملاحظة التالية:
* في السطور (31-37) من دالة `onLoginSubmitted()`:
  ```javascript
  const err = document.getElementById('error');
  const card = document.login.username.value.trim();
  if (!card) {
    err.innerText = 'يجب ادخال قيمة صحيحة!';
    showErrorPopup();
    return;
  }
  ```
  - **الملاحظة:** العنصر الذي يحمل المعرف `error` غير موجود في `index.html` (الموجود هو `popupMessage` أو `err`)، والدالة `showErrorPopup()` غير معرفة، حيث أن دالة التنبيه المعتمدة في المشروع هي `pop(message, type)`.
  - **الأثر العملي:** بما أن حقل الإدخال في HTML يحتوي على السمة `required`، فإن المتصفح يمنع إرسال النموذج فارغاً في معظم الأجهزة الحديثة، ولكن في حال تم الضغط المباشر على الزر في متصفحات قديمة جداً دون إدخال كرت، يجب الاعتماد على دالة `pop('يجب إدخال رمز الكرت!', 2)` لضمان عدم حدوث استثناء برمجي (JS Exception).
